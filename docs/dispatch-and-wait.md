# `dispatch-and-wait.sh` — синхронный запуск чужого workflow

Скрипт `.github/scripts/dispatch-and-wait.sh` запускает workflow в *другом*
репозитории и блокируется, пока этот запуск не завершится, после чего
пробрасывает наверх его код возврата. По сути он превращает асинхронный
`workflow_dispatch` («выстрелил и забыл») в синхронный вызов: вызывающая
GitHub Actions-джоба ждёт результат и падает, если целевой запуск упал —
благодаря чему её `needs:`-зависимости будут пропущены. Это тот же приём
оркестрации, что и `repository_dispatch`, только здесь запускается конкретный
workflow по имени с типизированными входами.

```
Usage: dispatch-and-wait.sh <org> <repo> [ref] [workflow] [php]
  ref       ветка; пусто -> ветка по умолчанию целевого репозитория
  workflow  по умолчанию build.yaml
  php       опциональный селектор PHP-минора, пробрасывается как -f php=<v>
```

## Пошагово

`set -euo pipefail` — строгий режим: падать на первой ошибке, ругаться на
необъявленные переменные, ловить сбой в любом звене пайпа.

**Аргументы.** `ORG` и `REPO` обязательны — конструкция
`${1:?org required}` при отсутствии аргумента печатает сообщение в stderr и
сразу выходит с ненулевым кодом. `REF` опционален: если он пуст, скрипт
определяет ветку по умолчанию цели через `gh repo view … defaultBranchRef`
(у старых репозиториев это `master`, у новых `main`). `WF` по умолчанию
`build.yaml`, `PHP` опционален (по умолчанию пусто).

**Сборка команды.** Базово `workflow run <WF> -R <ORG>/<REPO> --ref <REF>`;
если `PHP` непустой и не равен `all`, добавляется `-f php=<PHP>`. То есть `all`
и пустое значение трактуются одинаково — «вход не передавать, пусть цель
соберёт все версии».

**Снимок «до» dispatch.** Один и тот же фильтрованный запрос используется и для
снимка «до», и для поллинга — он вынесен в массив `list_args`:

```bash
list_args=(run list -R "$ORG/$REPO" --workflow "$WF" --branch "$REF"
           --event workflow_dispatch --limit 1 --json databaseId
           --jq '.[0].databaseId // 0')
before=$(gh "${list_args[@]}")
```

Берётся ID самого свежего `workflow_dispatch`-запуска этого workflow на этой
ветке (jq-оператор `// 0` подставит `0`, если таких запусков ещё нет). Зачем
это нужно: **`gh workflow run` не возвращает ID созданного запуска** — под
капотом dispatch-API отвечает `204 No Content` без тела. Поэтому свой запуск
приходится вычислять как «тот, которого не было до отправки». Критично, что
снимок «до» и поллинг используют **идентичные фильтры** (`--branch` +
`--event workflow_dispatch`) — иначе более старый существующий dispatch-запуск
можно принять за свой.

**Отправка и поллинг.** `gh "${run_args[@]}"` собственно отправляет workflow, и
начинается поллинг тем же запросом `gh "${list_args[@]}"` — до 40 итераций с
паузой 6 секунд (максимум ~4 минуты на *появление* запуска). Как только
найденный ID и не `0`, и отличается от `before`, цикл прерывается. Если за 40
попыток так и не нашлось (ID остался `0` или равен `before`), печатается
аннотация `::error::` (workflow-команда GitHub Actions, создающая ошибку в
логе) и `exit 1`.

**Ожидание:**

```bash
gh run watch "$rid" -R "$ORG/$REPO" --interval 15 --exit-status
```

`gh run watch` опрашивает запуск каждые 15 секунд и стримит статус;
`--exit-status` заставляет `gh` вернуть ненулевой код при неудаче. В связке с
`set -e` это и есть механизм проброса провала наверх. Жёсткого таймаута нет —
ждёт столько, сколько идёт целевой запуск.

## Какие команды генерируются

`dispatch-and-wait.sh acme web main`:

```bash
# снимок «до» и поллинг — один и тот же запрос (list_args):
gh run list -R acme/web --workflow build.yaml --branch main --event workflow_dispatch --limit 1 --json databaseId --jq '.[0].databaseId // 0'
gh workflow run build.yaml -R acme/web --ref main
gh run list -R acme/web --workflow build.yaml --branch main --event workflow_dispatch --limit 1 --json databaseId --jq '.[0].databaseId // 0'
gh run watch <rid> -R acme/web --interval 15 --exit-status
```

Лог: `Dispatched build.yaml on acme/web@main; locating the new run…` (без
суффикса про php).

`dispatch-and-wait.sh acme web release/2.0 deploy.yaml 8.5` — отправка
становится `gh workflow run deploy.yaml -R acme/web --ref release/2.0 -f
php=8.5`, а `run list`/`watch` идут с `--workflow deploy.yaml` и `--branch
release/2.0`.

`dispatch-and-wait.sh acme web main build.yaml all` — вход `php` **не**
передаётся: `gh workflow run build.yaml -R acme/web --ref main`.

## Острые углы

Эвристика «найти свой запуск» без ID имеет пределы. Текущее состояние:

1. **Рассинхрон фильтров `before`/поллинга — ИСПРАВЛЕНО.** Раньше снимок
   `before` брался *без* `--branch`/`--event` (самый свежий запуск вообще), а
   поиск — *с* этими фильтрами, из-за чего более старый существующий
   `workflow_dispatch`-запуск мог быть принят за свой (цикл прерывался
   преждевременно, `gh run watch` смотрел на чужой уже завершённый запуск →
   ложный успех/провал). Теперь снимок и поллинг используют один и тот же
   `list_args` с идентичными фильтрами `--branch $REF --event workflow_dispatch`.

2. **Только ветки, не теги/SHA — контракт.** Поиск фильтрует по `--branch $REF`,
   поэтому `REF` обязан быть именем ветки. Тег или SHA задиспатчатся, но не
   найдутся → таймаут (~4 минуты) и `exit 1`. Оркестратор передаёт либо явно
   заданную ветку, либо пустой `ref`, который скрипт превращает в ветку по
   умолчанию цели, так что на практике безопасно; ограничение зафиксировано
   комментарием в шапке скрипта.

3. **Гонка при параллельных вызовах — известное ограничение.** Если две джобы
   (например, matrix) одновременно диспатчат один и тот же workflow на одну
   ветку, у отправки нет идентификатора, и инстансы могут зацепиться за один
   запуск или перепутать «свой» с «чужим». Для параллельного фан-аута на один и
   тот же target+branch приём ненадёжен; надёжное решение требует корреляции по
   уникальному входу (маркер в `inputs`). Текущий DAG так не делает — все
   диспатчи идут на разные репозитории, — поэтому риск латентный.

4. **`php=all` в логе — ИСПРАВЛЕНО.** Лог-суффикс теперь берётся из отдельной
   переменной `php_note`, которая выставляется только когда `-f php=` реально
   добавляется в команду; при `php=all` или пустом значении суффикса нет.
